# CLAUDE.md

Members-only digital magazine for a club. Next.js (App Router) + Postgres + Cloudflare R2,
hosted on Railway. Admin authors page-based issues; members read a flipbook (desktop) or
scroll (mobile). Magic-link auth.

## Read before working

Core docs (long-lived — keep current):

- `docs/architecture.md` — system overview, directory map, data flow, routes, env.
- `docs/database.md` — schema, the content/block model, migrations, seeding.

## Workflow

Work is tracked as **GitHub issues** — one issue per task, small papercuts batched in a
grab-bag issue. The issue brief gives intent + acceptance criteria; the current code is the
source of truth for the _how_. Branch per issue; keep PRs reviewable. **`docs/workflow.md`
is the process doc**: triage/model-routing labels, the subagent-per-issue loop, the
orchestrator review pass, and the required gates per change type (browser pass, contrast
gate, `RENDER_VERSION`, …). Read it before working an issue.

Commit/PR titles follow conventional-commit style (`feat:`, `fix:`, `docs:`, `release:` …) —
a convention, not strictly enforced.

**Releasing to prod:** `main` is integration (auto-deploys the demo/staging site); the
members' site has **no branch of its own** — it deploys from a `v*` git **tag**. Ship by
publishing a GitHub Release (or `git tag vYYYY.MM.DD && git push origin <tag>`), which
fires the `Deploy to production` Action. See `docs/infrastructure.md#release-workflow`.

## Commands

- `docker compose up -d` — local Postgres
- `npm run dev` — local dev server
- `npm run db:generate` / `db:migrate` / `db:seed` / `db:studio` — Drizzle workflow: migrations are committed in `drizzle/` and run on deploy (`db:push` is a local iteration convenience only; see `docs/database.md`)
- `npm run db:admin -- you@example.com` — create/promote an admin user (first-run bootstrap; idempotent)
- `npm run ai:grant -- 25 "<note>"` — top up this month's AI assistant budget (see `docs/infrastructure.md#ai-assistant-budget`)
- `npm run demo:reset` — demo site only: wipe everything but members, settings and the AI spend ledger/grants, reseed the six issues, sweep unreferenced storage (see `docs/demo-content.md`)
- `npm run lint` / `npm run format` — lint / format
- `npm run changelog` — client-facing release email since the latest tag: highlights drafted into an editable notes file, full change list beneath, Proton Mail handoff (see `docs/changelog-email.md`)
- `npm run invoice -- invoices/<name>.yml` — client invoice PDF from a YAML config (local-only tool, data in git-ignored `invoices/`; see `docs/invoicing.md`)
- `npm run icon` — re-render the reference app-icon PNGs in `docs/assets/` from the live renderer (`src/lib/site-icon.tsx`), one per brand

## Status

Everything below is real and wired end-to-end — **nothing is stubbed.** Routes + directory
map in `docs/architecture.md`; phase plan in `docs/ROADMAP.md`.

- **Content** — library, reader, dashboard, editor are DB-backed (editor autosaves; reader renders saved issues).
- **Issue numbers** — a draft has none (it reads "Draft"); the number is chosen in the publish modal, proposed as the next in the published sequence and editable, and is final once published. Home and archive order by number, so a back issue published later never becomes "latest"; deleting a published issue frees its number.
- **Library + archive** — the home page features the latest issue over a capped run of recent back-issues (15) and links to `/archive` only once there are more, so it stays the same length however long the magazine runs. `/archive` is the whole back catalogue for members: paginated server-side with a DB-side title search and year filter, all three in the URL (`?q=`/`?page=`/`?year=`), sharing the members list's page control.
- **Admin lists** — issues, members and sponsors share one contract: paginated 25/page with DB-side search and filters, all of it in the URL (`?q=`/`?filter=`/`?page=`, plus `?year=` on issues) so a refresh or a `revalidatePath` lands where the admin was. The issues dashboard adds row selection that survives paging, searches and filters, "select all N matching" past the served page, and one bulk action — delete, confirmed with the total and the published subset, running the same per-issue asset cleanup as the single delete.
- **Issue transfer** — an admin exports selected issues from the dashboard as one zip (content, images, and the sponsors and logos they reference) and imports it on another copy of the site, where each issue arrives as a fresh numberless draft and no email is ever sent. Images travel byte-for-byte and are resolved **per use**: a cover logo whose name matches one already here takes the destination's mark, while an ordinary photo block showing the same artwork keeps the bundled bytes. Sponsors and logos match by name — a single match is reused exactly as it is, two refuse the import and name it. Anything the bundle doesn't supply is cleared rather than carried, and reported. The archive is validated whole before a row is written, against the editor save path's own rules; every object an import writes lives under `imports/<operationId>/`, so a failure deletes that prefix at once and an abandoned attempt is swept later. The operation id makes a retry after a dropped connection return what happened rather than a second set of drafts. Format and limits: `docs/issue-transfer.md`.
- **Editor undo/redo** — a capped (100) snapshot history of the document and the author's place in it: every structural edit (insert, delete, move, reorder, cover toggle, page add/delete, an overflow split) undoes and redoes in one step, back on the page it happened to; a run of edits to one field folds into one. Text inside a block still undoes finer through Tiptap — the editor-level Ctrl/Cmd+Z (Shift+Z / Y to redo) stands down while focus is in a text entry. Undo and redo join the insert buttons and the cover toggle in one pill along the foot of the canvas.
- **Page overflow** — a block that outgrows its page is marked at the page's text limit in the editor, with one action beside it: body text splits at the last top-level node that fits (cascading onto as many pages as it needs), any other block moves whole onto the next page. Edit-time only — content never reflows at read time.
- **Images** — editor uploads (WebP via sharp), served from R2 when configured, else a local-disk fallback (`.data/uploads`) so it works with no cloud setup. A photo can also take the **whole page** (content v6), two ways: **Fill page** covers the canvas edge to edge and trims the photo to the page's shape, **Fit page** grows the photo whole until its first edge touches and centres it against page-coloured bars. Either way it owns the page — the running footer and the theme's page decoration stand down rather than print over it, the caption is dropped (alt text stays), and on interior pages nothing else may be added. Pressing either on an interior photo that shares a page moves the photo onto a page of its own in one undoable step; switching between the two is a plain edit. Interior full-page images are image-only. On covers, Fill/Fit sets the background beneath the existing editable blocks. Independent panel, text and shadow colours (magazine swatches or custom hex), a panel shape that either fills the item or fits each wrapped line of text (content v10), shadow strength and text size retain the magazine typography. Selected words support bold, italic, underline, colour and shadow; six older contrast presets remain readable. Cover frame and running masthead have separate toggles. Selecting a new background preserves the former one as a normal image; demoting a cover with overlays restores ordinary flow.
- **Cover elements** (content v7) — one **Story** element (an optional list heading, blank by default and ghosted "Inside this issue" in the inspector, one to six linked or free-standing stories and a stored headline size), issue details and resizable library logos on plain or photographic covers. On a cover the toolbar's **Text** tool opens a menu — Paragraph, Story, Details — with Logo beside it. A side inspector (dockable to either side of the page) holds each item's placement, width, alignment, appearance and content; a floating bar over the selected item formats the selected words; overlapping items can be layered forward and back; existing headings/text/images can also be positioned independently. Section references follow heading edits and pagination, with custom cover-title overrides. Phone layouts reflow into reading order; editor warnings flag collisions, overflow and missing references. All edits support history and autosave.
- **PDF import** — the editor's right-hand side panel (tool rail on the editor's edge, slides in, drag-to-resize) hosts **Import PDF** on interior pages; its button stays visible but unavailable on covers. A local PDF is parsed in the browser (PDF.js in a same-origin worker, nothing uploaded) and shown on a stage that fits, pans and zooms like the magazine canvas, with the tools floating at the foot as they do on the canvas and the panel's Close and Replace PDF hung under the rail button; its text blocks and photos are drawn as selectable regions over the rendered page, each with a suggested block kind (heading / text / image) that a small tool pill can retype or split; a selection (or _Select all on page_) is added in one measured, undoable step after the selected block, fitting onto continuation pages as needed, or a region is dragged out and dropped at a place on the page, previewed there as the block it becomes, on drafts and published issues alike. `docs/pdf-import.md` has the limits and the production gates.
- **Auth** — magic-link (Auth.js v5, ~90-day DB sessions), members-only. Library/reader need a member session (signed-out → `/signin` with a validated `?next=`); `/admin`, server actions and uploads need `is_admin` (`npm run db:admin` bootstraps one). Dev logs the link to the console (no Resend needed).
- **Members** — admin manages the `users` table (add / remove / toggle subscribed / toggle admin / CSV import) with guard rails (no self-removal, always ≥1 admin); the list is paginated with server-side search and status filters (`?q=`/`?page=`/`?filter=` in the URL), and selections survive across pages, searches and filters. The CSV import validates row by row — invalid addresses are skipped and named in the result, never failing the batch — with the browser preview and the server sharing one address test (`src/lib/member-email.ts`) and one batch cap (`src/features/members/import-limit.ts`).
- **Sponsors** (content v2) — `sponsors` table + `/admin/sponsors` (logo upload, link, `activeUntil` w/ expired flag); sponsor blocks reference a managed sponsor via the editor picker (manual entry retained as the v1 fallback; v1 inline blocks still render). The list searches by name and filters all / active / expired.
- **Magazine details** — `settings` table (one row) + `/admin/magazine`: the owner edits the magazine name, club name and tagline, whether the classic theme prints its running head — the magazine name and issue number — above the page content, and the page footer's appearance (mark size and text size — Small/Medium/Large presets or a Custom number of px within caps, mark 12–48 / text 8–16 — and alignment), with a live preview built from the real page components. Effective value = DB → `NEXT_PUBLIC_*` env → shipped default, resolved in `src/server/settings.ts`; the env vars are bootstrap defaults only, and a deployment that never opens the page renders exactly as before. No redeploy to change any of it.
- **Logos** — `logos` table + the logo library on `/admin/magazine` (`/admin/logos` redirects): the club's own marks (crest, fern, wordmark), uploaded through the shared image pipeline (transparency preserved), named, renamed and deleted. Deletion is refused while a logo is referenced.
- **Page footer** — an issue can carry a mark (`issues.logoId`, picked in the editor header). Covers omit the running footer on every page surface, including thumbnails; theme decoration stays. With a mark, each interior page's running footer sets the mark and the club name as one lockup at the footer's ordinary tracking, with the page number out at the opposite margin; the mobile reader (which has no pages) closes with the same lockup, and marks the foot of each page but the cover with a small "Page N" — the numbering the discussion's page tags use. Wording, mark size, type size and alignment all come from the magazine settings. With no logo the original text-only footer renders unchanged (taking only the type size). The footer's **height** is clamped per issue: each issue records the footer sizes its pages were laid out against (`issues.footerMarkSize`/`footerTextSize`, whole px), and every surface resolves `settingsForIssue()` (`Math.min` per axis, then held to the caps) — so a footer the owner later enlarges reaches the issues with room for it, never prints over an already-full page, and is adopted per issue in the editor where the overflow marker catches what no longer fits.
- **Discussion** (epic #298, complete) — the six lines below, all behind one switch, `settings.comments_enabled` (default off), which the owner turns on at `/admin/magazine`; off hides every surface and refuses every member write, deleting nothing. The overview, the go-live steps and the gates are in `docs/architecture.md` → Discussion; phase 2 is parked in #305.
- **Discussion storage** (#299) — the tables (`member_names`, `comments`, `comment_reports`, `notifications`), the server module and the posting-name rules. Removing a member applies the owner's `removed_member_comments` policy (default anonymise) and removes their avatars. See `docs/database.md`.
- **Member profile** (#300, epic #298) — `/profile`, reached from the library header's avatar (the default posting name's photo, else initials) and the footer's Email preferences link; `/preferences` 308s to it. Both email toggles live there (new issues = `subscribed`, replies = `reply_emails`, off by default). While discussion is on it also manages the account's **posting names** — up to 5, validated in the browser and again on the server, a shared name saved with a gentle note, a used name retired rather than deleted, the last one kept — with a photo each through `POST /api/profile/avatar` (session, same origin, the name's owner, ≤ 5 MB, sniffed bytes, 5/hour; centre-cropped 256px WebP; the previous photo's row and object removed in the same step) and, for an admin's own names, an opt-in Admin badge. The admin members list shows each member's posting names, and **Posting names…** in the row renames, retires or clears the photo of any of them — an admin's retirement sticks (the member can't add the name back), and a retired name can still be reworded.
- **Discussion thread** (#301) — every published issue has a thread in the reader, opened by a green speech-bubble button — top right beside the Theme toggle on a computer, bottom right on a phone, with no count on it. On a computer it is a drawer floating in from the right over the flipbook (the contents rail's twin, the spread untouched); on a phone a bottom sheet (swipe-down, close, Escape and Back all close it; it rides above the on-screen keyboard). One thread component in both: oldest first, one level of replies folded under a "N replies" toggle, plain text, relative times, "(edited)", the Admin badge, "Comment removed" stubs that keep their replies, and "Former member". Members post, reply, edit or delete their own and report anyone else's (always thanked); "Posting as" picks one of the account's names per comment, and an account with none names itself in the composer with its first post. Fetched only when opened (`GET /api/issues/[number]/comments`, member-gated) and after each write; `?discussion=1[&comment=<id>]` opens it and highlights the comment, and the address always says whether it is open (Back closes it; closing drops the parameters). Library cards say "N comments"; the admin's delete confirmations (single and bulk) count the comments that go. Nothing shows while discussion is off, on drafts, or in print/PDF; demo mode's signed-out visitor sees only a sign-in panel.
- **Moderation** (#302) — `/admin/reports` lists every report in the shared admin list contract (search over the comment, posting name and reporter; open / resolved / all; 25 a page), each with the comment as reported beside what became of it (edited, deleted by its author, removed by an admin), and Hide/Unhide, Delete, Resolve, Clear avatar and Retire name; hiding or deleting resolves every open report on the comment. The admin nav and the Issues summary carry the open count. A new report emails every admin (after the commit, never failing the report, at most one per 15 minutes, then "N open reports"). `/admin/magazine` holds the **Discussion** switch — the way the club turns discussion on — and the removed-member choice; the members removal confirmations (single and bulk) say how many comments go and what happens to them. In the thread an admin sees every comment — hidden ones greyed with their words and a Hidden pill, deleted ones as a marked stub — with "Account: <name>" (linking to the members list) under any posting name that differs from the account's name, never the email; Hide / Unhide on every comment and a confirmed Delete on anyone else's, through the same functions as the inbox, so reports resolve either way. Members' payload and view are unchanged.
- **Reply notifications** (#303, epic #298) — a reply to someone else's comment lights a **bell** in the library header: the unread count from the page's server render (no polling) and a menu of the newest 20 — "Ada replied to your comment on Issue 14", or on an account with several posting names whose comment it was — where choosing one marks it read and opens the thread on the reply, with Mark all read at the foot. A member who turned reply emails on at `/profile` also gets one email per reply: the posting names only, member text escaped, a **Read the reply** button that is a personal magic link (minted by `src/server/magic-link.ts`, shared with the publish blast) and a **Stop reply emails** link — a `replies`-purpose unsubscribe token that flips only `reply_emails`, while the issue-unsubscribe tokens already in inboxes keep working unchanged. Nothing while discussion is off; hidden or deleted replies drop out of the bell.
- **Page tags** (#304, epic #298) — a comment can tag any page of the issue through a compact "Tag a page" pill beside "Posting as": a menu of "No page" then every page in order, each with its first heading as a hint and the page(s) open now marked "open now" (repeated at the top from page 6 on). The open pages are both halves of a desktop spread (or the cover) and, on a phone, the section being read, frozen while the sheet is up. The choice resets to "No page" after each post; replies are never tagged. The two pills share one row with Post in the desktop drawer and take their own row above it on a phone. The comment stores the page's **id**, and its chip ("Page 12", "The cover") reads the number from the issue as it stands, so an overflow split that renumbers pages still names the right one and a deleted page reads "Page removed", disabled. The chip turns the flipbook with the drawer left open, or closes the sheet onto the page's section with focus there. A **filter** funnel in the thread's header opens a panel: a search over words and names (matches marked, a matching reply opens its thread), **Show** — all, this page (both on a spread, following the reader), my comments, or any page — and **Sort** (oldest, newest, most replies); pages narrow server-side (`?page=` on the list route), the rest on the loaded list. A status line with **Show all** says what a narrowed list holds — the button stays count-free; a page change asks again.
- **Publish email** — publishing can email each subscribed member a personal magic link that opens the issue (the email _is_ the sign-in link; skippable, off by default on re-publish), with a signed one-click `/unsubscribe` (no session). Dev logs blast + unsubscribe links.
- **PDF export** — members-only `GET /api/issues/[number]/pdf`, prints fixed-canvas pages to a paginated PDF via headless Chromium (Playwright), cached in R2 by issue id + revision. Server-only and off the request path via a token-guarded print route; needs Chromium in the deploy container (`docs/infrastructure.md`). The owner can switch downloads **off site-wide** from `/admin/magazine` (a `settings` column, same DB → env → default chain, no redeploy): the button isn't rendered anywhere and the route refuses with 403. The internal print route stays reachable — turning downloads off is a distribution choice, not a rendering one — and cached PDFs are neither deleted nor rebuilt, so switching back on restores them instantly.
- **AI assistant** (epic #306, in progress, dormant) — `docs/ai-assistant.md` holds the decisions. Built so far: the spend ledger and budget (#307) — `ai_usage` (one row per model request, cached tokens counted apart and priced from the dated table in `src/lib/ai-pricing.ts`; an unpriced model is refused), `ai_grants` (the owner's top-ups via `npm run ai:grant`) and `src/server/ai-budget.ts`, which resolves the UTC month's allowance (`AI_MONTHLY_BUDGET_USD`, default 0) + grants − spend, a run's spend and the daily rollup. No UI and no model calls yet.

## Stack

Next.js 16 · React 19 · TypeScript · Tailwind v4 · Drizzle ORM (Postgres) ·
Auth.js (magic link) · Resend (email) · R2 via AWS S3 SDK · sharp (WebP) ·
custom CSS-transform flipbook (`reader-spread.tsx`) · Playwright (on-demand PDF).

## Non-negotiables

- Keep files under 500 lines; see `docs/design-principles.md` for the full rule set.
- Server Components by default; `"use client"` only when needed.
- Validate all external input with zod; never expose secrets to the client.
- If adding comments to code, keep them concise and to the point. One or two lines of explicit description is better than an essay. Only add more detailed explanations if the code change deserves it and subsequent readers would benefit.
- Build for an older, phone-heavy, accessibility-sensitive audience.
